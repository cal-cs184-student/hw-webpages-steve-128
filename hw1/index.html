Task 1: Drawing Single-Color Triangles

Implementation Details

  1. Find the min/max of x and y among the three vertices to bound the triangle via a rectangle.
  2. Use floor() for minimum and ceil() for maximum to ensure all pixels are covered.
  3. Ensure x, y is within 0 to width-1 and 0 to height-1, respectively.
  4. Return early if signed area is 0.
  5. Sample at pixel center: (x + 0.5, y + 0.5).
  6. Compute edge function values for all 3 edges.
  7. If all 3 have the same sign (all ≥ 0 or all ≤ 0), call fill_pixel().
  8. Loop over pixels in the triangle’s bounding box, which is the smallest rectangle that contains the triangle.

Task 2: Antialiasing by Supersampling

Why is supersampling useful?

Supersampling is useful because it helps reduce aliasing artifacts in images. By sampling multiple points within each pixel and averaging their contributions, it produces smoother edges and more visually coherent results. This is especially useful for rendering high-contrast edges, such as triangle edges, where aliasing can be particularly noticeable.

Modification details:

  1. Modify set_sample_rate() so that the buffer size changes dynamically with the sample rate.
  2. In fill_pixel(), loop over sample_rate and set all subsamples for pixel (x,y) in sample_buffer to the same color.
  3. Downsample by averaging samples corresponding to each pixel in resolve_to_framebuffer().
  4. Scale up coordinates by sqrt(sample_rate) in rasterize_triangle() and rasterize on the supersample grid by testing each subsample center. Write the triangle color into the corresponding slot in sample_buffer if it's inside.

Task 4: Barycentric coordinates

Barycentric coordinates:

Barycentric coordinates describe a point P inside (or on) a triangle as a weighted combination of its three vertices. For a triangle with vertices A, B, and C, the barycentric coordinates \((\alpha, \beta, \gamma)\) of a point P satisfy: \[ P = \alpha A + \beta B + \gamma C, \quad \text{where } \alpha + \beta + \gamma = 1. \] The values \(\alpha\), \(\beta\), and \(\gamma\) represent how much each vertex contributes to the point P. For points inside the triangle, all three weights are nonnegative. If the vertices have colors, barycentric coordinates let us smoothly interpolate the color at P using the same weights: \[ \text{Color}(P) = \alpha\,\text{Color}(A) + \beta\,\text{Color}(B) + \gamma\,\text{Color}(C). \] In the example triangle, the top vertex is blue, the bottom-left vertex is red, and the bottom-right vertex is green. Near the blue vertex, \(\alpha\) is large, so the color looks more blue; near the red vertex, \(\beta\) is large; near the green vertex, \(\gamma\) is large. At the center of the triangle, the weights are more balanced, so the color becomes a mix of all three. At each vertex, the corresponding weight is 1 and the others are 0, so the color matches the vertex color exactly. This is why barycentric coordinates produce a smooth gradient across the triangle.

Task 5: "Pixel sampling" for texture mapping

Pixel Sampling:

Pixel sampling is a technique used in texture mapping to determine the color of a pixel on the screen based on the corresponding point on a texture image. When rendering a textured surface, we need to map each pixel on the screen to a point on the texture. However, the texture image is discrete, and the point we want to sample may not correspond exactly to a single pixel in the texture. Pixel sampling addresses this by using interpolation to compute the color of the pixel based on the colors of the nearby texture pixels. There are two main different approaches to pixel sampling: nearest-neighbor sampling and bilinear interpolation.

Nearest-Neighbor Sampling:

I implemented nearest sampling by taking the interpolated (u, v) at each covered sample, clamping it to [0,1].Then I map it to texel space and round it to the closest integer texel index. Finally, I fetch that single texel and display it.

Bilinear Interpolation:

For bilinear sampling, after mapping (u, v) to (x, y), I take the 2×2 neighborhood around it. I compute the fractional part of (x, y) to get the weights for interpolation. Then I fetch the colors of the 4 neighboring texels and blend the four texels by linear interpolation in x twice and y once.

Task 6: "Level Sampling" with mipmaps for texture mapping

Level Sampling:

Level sampling is a technique used in texture mapping to select the appropriate level of details from a mipmap when rendering a textured surface. Mipmaps are precomputed, downscaled versions of a texture that are used to improve rendering performance and reduce aliasing artifacts when textures are viewed at a distance. When a texture is zoomed out, sample from the full-resolution image can cause aliasing. Level sampling addresses this by selecting a lower-resolution mipmap level that better matches the size of the texture on the screen.

Implementation details:

  1. In rasterize_textured_triangle, I compute the UV at (x, y), (x+1, y), and (x, y+1) via barycentric interpolation.
  2. In Texture::get_level(sp), I compute the UV differentials and use the maximum of the absolute values of the differentials to determine the appropriate mipmap level. I also clamp it to [0, max_mip_level]
  3. In Texture::sample(sp), I handle different mipmap levels and pixel sampling combinations. Then, I pass in the appropriate mipmap level to the sampling function.

Tradeoffs:

  1. Pixel sampling: Affects how smooth the texture looks within a single mip level, with nearest sampling being faster but less smooth, and bilinear sampling being smoother but slower. It uses no extra memory.
  2. Level sampling: Uses mipmaps to reduce aliasing artifacts by sampling a prefiltered lower resolution texture. This is much better at stabilizing textures when zoomed out, but it requires additional memory for storing the mipmap levels.
  3. Supersampling: Runtime and the sample buffer memory both grow roughly proportionally with the number of samples per pixel while being able to produce higher quality antialiasing results.
